## 5. 9.3 从出行目的地到经过通道

### 讲什么

用同一地图范围切换两种流，直观解释区别：

- 出行流来自一次行程的解锁区域和上锁区域，展示骑行的起终点联系。
- 通道流来自匹配路径相邻区域的转移，展示骑行经过的区域连接。

可以在图旁画一个很小的示意：行程从 A 出发，在 C 结束，中途经过 B。出行流记 A→C，通道流记 A→B、B→C。示意不占用算法章的公式篇幅。

先看出行流中的强起终点关系，再切到通道流，关注岭兜-3→岭兜-4→观音山-2连续出现的连接。最后用片区弦图把众多区域对收束成可读的片区联系；同片区内不同区域之间的流动也有保留。

## 6. 9.4 东部案例：沿岭兜进入园区

### 讲什么

主案例选 **岭兜-2 → 岭兜-3 → 岭兜-4**，对应 `72 → 149 → 150`。它把前面的三类证据接起来：源汇上有出发与到达差异，通道图上有相邻连接，通勤链表中又有重复出现的完整顺序。

区域定位可结合道路说明：岭兜-2沿吕岭路；岭兜-3涉及吕岭路、前埔东路与观日路；岭兜-4主要涉及观日路、前埔东路。由此把故事落到软件园二期周边。道路名称来自本地路网与区域分析几何的相交结果，区域编码仍使用界面原名。

### 城市背景怎么接

软件园二期是一个有大规模日常到岗需求的园区。2021 年 5 月的现场报道，在软件园二期园区介绍中记录了 1,300 余家企业、6.7 万余名员工，可以作为接近采样时期的就业规模背景。正文取“约 6.7 万名员工”这一项即可。[人民论坛网现场报道，2021-05-07](https://www.rmlt.com.cn/2021/0507/613054.shtml)

交通背景使用下面这个准确的时间关系：采样时地铁 2 号线已运营，岭兜、软件园二期、观音山等站点已开通。因而这一带的骑行可结合“居住片区至园区的短距离通勤，以及轨道交通末端接驳”来解释，不需要把它归因于没有地铁。[2 号线开通报道，2019-12-25](https://fjnews.fjsen.com/wap/2019-12/25/content_30106810.htm)、[软件园二期站资料](https://zh.wikipedia.org/wiki/软件园二期站)、[岭兜站资料](https://zh.wikipedia.org/wiki/岭兜站)

这段是结合地图与城市背景的功能解释；图中的直接发现是骑行区域顺序与出发时段。正文以“与园区到岗及周边接驳需求相吻合”连接两者即可。

## 8. 9.6 西部案例：中心城区的双向局部网络

### 核心故事

**西部中心城区存在大量邻近区域之间的双向流动，源与汇交错分布。这里的活跃程度需要结合开关锁总量和流图阅读。**

这部分建议安排三幅图，依次解决“浅色区域是否活跃”“流量在附近怎样往来”“有没有具体的常见连接”。它与东部园区集中汇聚形成对照，也能解释此前讨论中没有展开的西部地图。

### 8.1 浅色区域里的高活动量

主角选厦禾路-1，id 1，涉及厦禾路、湖滨西路、禾祥西路和湖滨南路。完整早高峰日均解锁 1,662.50、上锁 1,513.25，两者合计 **3,175.75 次事件**，净流入为 -149.25。附近厦禾路-5和嘉禾园-1则分别净流入 +464.25和 +397.25。

写作重点是“出发、到达同时密集发生，净变化只显示其中的差额”。把这句话与源汇地图和厦禾路-1详情一起呈现，就能解释为什么不能只盯着最深的红蓝色。

### 8.3 一条更早活跃的西部连接

### 8.4 现实背景怎么接

西部使用“成熟中心城区中的居住、商业办公和交通节点近距离混合”作为解释。可以用以下资料中的一两条支撑，避免把每一个红区都指定成某栋办公楼。

- 湖滨一里至四里是 1980年代至1990年代初形成的多层住宅区。城市规划设计方的回顾记载，改造范围约30公顷，原有住宅4,898套、商铺130户、居民约2万人。这是湖滨一带既有居住与沿街商业并存的具体背景。[侯雷，厦门湖滨片区案例，2025年回顾](https://upforum.wupen.org/Data/View/1168)
- 2020年4月的同期报道已记载湖滨改造范围约30公顷、涉及单位和居民住户5,000多户，可用作同期资料入口。[人民网，2020-04-21](https://fj.people.com.cn/n2/2020/0421/c181466-33964923.html)
- 湖滨中路站在2020年末已投入使用，当时的现场报道记录了站口及附近公共空间的活动。它可以帮助解释湖滨区域中的公共交通连接背景。[人民网，2021-01-03，记述2020-12-31现场](https://fj.people.com.cn/n2/2021/0103/c181466-34508020.html)

前两项描述现实中的湖滨居住片区，作为西部片区背景使用，不把“2万人”直接填入某个算法区域的人口属性。叙述可以落在“这样的空间组合，与地图上近距离、双向、多目的地的骑行联系相吻合”。

西部小节的落点：源汇地图展示供需差额，流图和通勤链展示实际往来；二者一起读，才能看清一个已经很活跃的中心城区。

### 11.2 本文数字如何取得

本次直接读取已有 Parquet，不重跑 Spark 管线。统计所用的区域编码来自 `labels.py` 的 `region_codes`，并与 `config/district-labels.json` 对应。

| 数字 | 数据入口 | 取数规则 |
|---|---|---|
| 区域每小时/整段日均值 | `data/processed/region_profiles/region_metrics/` | 选四个晴天和指定小时，按区域累计可加量后除以4；上锁减解锁为净流入 |
| 净流入强度 | 上表及 `data/processed/regions/regions/` | 日均净流入除以该区域 `area_km2` |
| 过境率 | `region_metrics` | 合并后 `sum(tracks_transit) / sum(tracks_visiting)` |
| 出行流与通道流 | `data/processed/region_profiles/flow_od/`、`flow_channel/` | 出行流对距离档求和；两种流都对晴天和所选小时求和后除以4 |
| 仅显著与排名 | `data/processed/validation/flow_significance/` | 选对应矩阵、`scope=clear-days-stable`、`is_significant=true`，排除自环，再按权重降序、起终区域ID升序排序 |
| 链支持度与小时分解 | `data/processed/region_sequences/sequence_patterns/` | 选 `scope=clear-days` 和指定 `pattern`；`support_h06`至`support_h09`是一般支持度分解 |
| 链在界面中的资格与排名 | `api.py` 的 `_read_sequences`、`sequence_support_scan/` | 0.001档绝对连续支持度门槛为72；要求各步相邻，按连续支持度、长度降序和区域ID序列升序排列 |
| 道路定位 | `data/processed/network/network_segments.parquet` | 与区域分析几何相交，查看相交道路名称；不把它作为界面已有的承载街道统计功能 |

同一条链的一般支持度与连续支持度不同，小时分解按前者标注。岭兜三段链两者都为334，因此其292/334可直接作为连续案例的8点时段占比；嘉禾园两段链的小时分解标为“一般支持度分解”。
