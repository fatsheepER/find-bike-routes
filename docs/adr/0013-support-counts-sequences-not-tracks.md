# 支持度按区域序列条数计，是一票制的显式例外

计划第 3.3 节定的通行原则是「每条有效轨迹一票」，而频繁序列的支持度按含该模式的**区域序列**条数计：一条轨迹被路径断点或无区域段切成多段时，同一模式可能被它投出多票。实测每轨迹 1.03 条序列（晴天集 47,803 条序列 / 46,335 条贡献轨迹），偏差量级约 3%。

接受这 3%，是为了让挖掘留在 Spark MLlib 的 `PrefixSpan` 上。它的输入单位是行、输出只有 `sequence` 与 `freq` 两列，没有任何方式把支持度改成「含该模式的轨迹数」；要按轨迹去重就得自研整个序列挖掘，而「用 Spark MLlib 做挖掘」正是课程评分维度①的交付物之一。反过来，把整条轨迹拼成一行也不行：那会让被断点切开的两段之间产生一次实际不存在的相邻关系，连续子序列的计数随之失真。

## Consequences

- `CONTEXT.md` 的「支持度」词条写明这是一票制的显式例外及其量级。
- `sequence_support_scan` 每行并列给出序列条数、有效轨迹数与两者之比，读者可自行判断膨胀幅度。
- 与 `flow_channel` 的对照因此不是恒等式：长度 2 的连续模式支持度只按序列计，通道流按轨迹去重计，前者恒不小于后者。
- 但这 3% 是**库级**膨胀，落到区域对上要小一个数量级。只有同一条轨迹的多条序列含同一个有向区域对时，膨胀才落到那一对上；而切段点是路径断点与无区域段，切开的两侧是同一次骑行的不同部分，很少重复同一个相邻转移。晴天集实测（`recorded.region_sequences.flow_channel_contrast`）580 个共享区域对合计 77,580 对 77,520，即 +0.08%；532 对完全相等，单对最大 +6.82%，Spearman ≈ 1.00（0.99998，四舍五入到四位记作 1.0），没有一对低于通道流。方向与构造一致，差额比 3% 小不是口径错位：556 个 `tracks ≥ 14` 的通道流区域对全部出现在挖出的长度 2 模式里。
- 该对照只作 `recorded` 旁证，不写成断言。报告引用时用对级的 0.08%，不要把库级的 3% 当成对级差额。
