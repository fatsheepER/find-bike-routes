# 取消泊位供需分析，围栏数据退出项目

计划第 5 节要用围栏面积密度当供给、净流入强度当需求，识别失衡区域并输出调度建议。我们取消这一项，围栏数据整体退出项目：不入库、不上前端、从数据契约锁中移除；评分维度 ④ 的业务功能改为区域画像与显著流对识别。notebook §6.1 / §6.6 的原型保留为研究证据，不移植。

理由有两条。第一，数据不够支撑这个结论：围栏表只有多边形，没有容量，面积中位数 10 m²，用面积当供给是代理量；需求侧只有四小时早高峰的存量变化，没有停放峰值。两个代理量相除得出的「失衡」没有任何可观测事实能对照。第二，挖掘项已经够多——源汇、过境率、双方向集中度、功能构成、三张流矩阵、频繁序列、零模型——每多一项结果，前端就多一块侧栏与一套交互，而前端工作量是本项目的硬约束。

## Considered Options

- 只退出分析、围栏仍作前端被动图层：留下一张没有消费者的表，答辩时反而要解释为什么有围栏却不分析。
- 用容量代理（围栏面积 / 单车占地）继续做：多一个拍出来的常数，结论仍然无法对照。

## Consequences

- `docs/project-plan.md` 中泊位与围栏的七处引用删除或改写；`config/data-contract.lock.json` 去掉围栏 raw 与 staging 两条并重新冻结。
- CONTEXT.md 不定义围栏、泊位供给、泊位失衡。
- MobilityDB 不建 `fence` 表，`region_metrics_daily` 不含泊位列，前端侧栏不含泊位供需。
