# 粒度敏感性只比出行流的 Top-K，通道流不跨格边长比

计划第 7 节要求报告 150/200/300 米下「区域划分与 Top-K 区域对的变化」，没指定是哪张矩阵。通道流不参与跨格边长的比较，因为它不可归因：通道流由「匹配路径穿越的区域序列」定义，而一次进入的够格门槛是 100 米路径或 2 个匹配点——换格边长同时改变了穿越判定与够格门槛，比出来的差异分不清是区域边界变了还是穿越判定变了。出行流只依赖订单端点的区域归属，格边长只通过区域边界影响它，差异可归因到边界。

顺带的代价是备选划分不必把 `region-context → assign-regions → region-profiles` 跑两遍（两个备选格边长共八次阶段运行）：出行流矩阵在 `validate-partitions` 阶段内部按同一套最近区域回落规则直接算出。

## Consequences

- 200/300 米那两行只有出行流的 Top-K 重合率；报告必须写明通道流不参与及其理由，否则读者会以为漏做。
- 粒度臂的出行流矩阵是第二处实现「订单端点 → 区域」。150 米那一行按构造等于采纳划分，其 Top-K 重合率恒为 1，这一行就是该实现的自检行。
- `data/processed/validation/` 下的备选划分永不被任何下游阶段引用；`assign-regions`、`region-profiles`、`region-sequences` 的 `--regions` 只接受冻结划分。
- `min_component_cells` 按面积等价折算并向上取整（200 米 8 格、300 米 4 格）；对齐区域尺度时只动 `markov_time`，不动这个下限——两个变量一起动就无法归因。
