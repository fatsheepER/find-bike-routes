# 划分相似度以匹配点为元素，单元格口径退为辅

跨格边长的两套划分没有共同的单元格：150 米与 300 米的格对不齐。可选的公共元素有两个——50 米公共细网格，或匹配点。选匹配点。细网格会把 ADR-0010 已经踩过的坑再放大一次：格网四邻接骨架本身就贡献 AMI，而把一个 300 米区域摊成 36 个元素只让权重反映面积、不反映流量。匹配点是流量的实际承载者，天然按流量加权，且任何格边长都成立。

因此第 7 步全部划分相似度统一以点为主口径（`ami_points`，元素中心相似度同样以点为元素），单元格口径（现成的 `assignment_ami`，交集口径）只在同格边长的臂上作辅口径，以便与 §4 `markov_scan.pairwise_ami` 接得上。落在无区域单元格上的点直接丢弃并报告占比，不做最近区域回落——回落是订单端点的规则，把它引进相似度会让无覆盖区域的边界也参与打分。

## Consequences

- 同一个概念有两列（`ami_points` 与 `ami_cells`），表里并列，报告引用点口径；两列差得远本身就是一条结论（说明差异集中在低流量区域）。
- 150 米那一行与采纳划分的点口径 AMI 恒等于 1，是元素映射实现的自检行。
- 元素中心相似度自实现 flat 版（α = 0.9），用三个手算例钉住，不引 clusim、不写参考实现。
- 四折比较的是走完四步后处理的区域，不是 Infomap 原始社区；原始社区的 AMI 另存一列以便与 §4 的扫描表对齐。
